# RsOJ Control Panel - 新增功能文档

## 概述
控制面板现在包含三个主要的新功能模块：系统监控、用户管理和题目管理。

## 1. 系统监控 (System Monitor)

### 功能特性
- **系统状态实时监控**
  - 数据库连接状态
  - 活跃 WebSocket 连接数
  - 服务器运行时间
  - 内存使用情况（Linux系统）

- **数据库统计**
  - 用户总数
  - 题目总数
  - 提交总数
  - 讨论总数
  - 数据库大小

### API 端点
- `POST /api/system-status` - 获取系统状态
- `POST /api/database-stats` - 获取数据库统计

### 实现文件
- `src/system_monitor.rs` - 核心监控逻辑

---

## 2. 用户管理 (User Management)

### 功能特性
- **用户列表查看**
  - 分页浏览所有用户
  - 搜索用户（按用户名或邮箱）
  - 显示用户基本信息、提交数、状态等

- **用户操作**
  - 封禁/解封用户
  - 删除用户（级联删除相关数据）
  - 查看用户详细信息

- **用户详情**
  - 注册时间
  - 最后登录时间
  - 提交总数
  - AC 数量
  - 讨论数量

### API 端点
- `POST /api/users` - 获取用户列表（支持分页和搜索）
- `POST /api/users/:id` - 获取用户详情
- `POST /api/users/:id/ban` - 封禁用户
- `POST /api/users/:id/unban` - 解封用户
- `POST /api/users/:id/delete` - 删除用户

### 实现文件
- `src/user_management.rs` - 用户管理核心逻辑

---

## 3. 题目管理 (Problem Management)

### 功能特性
- **题目列表管理**
  - 分页浏览所有题目
  - 搜索题目（按标题或 ID）
  - 显示题目统计（提交数、通过率等）

- **题目操作**
  - 创建新题目
  - 编辑题目信息
  - 显示/隐藏题目
  - 删除题目（级联删除相关提交）

- **题目信息**
  - 标题、描述
  - 输入输出格式
  - 难度级别
  - 时间限制、内存限制
  - 提交统计和通过率

### API 端点
- `POST /api/problems` - 获取题目列表（支持分页和搜索）
- `POST /api/problems/create` - 创建新题目
- `POST /api/problems/:id` - 获取题目详情
- `POST /api/problems/:id/update` - 更新题目信息
- `POST /api/problems/:id/toggle-visibility` - 切换题目可见性
- `POST /api/problems/:id/delete` - 删除题目

### 实现文件
- `src/problem_management.rs` - 题目管理核心逻辑

## 前端界面

### 导航结构
新的控制面板包含以下页面：
1. **System Monitor** - 系统监控仪表盘
2. **Analytics** - 原有的分析图表（访问量、注册等）
3. **Users** - 用户管理页面
4. **Problems** - 题目管理页面
5. **Database** - 数据库管理（清空数据库）

### UI 特性
- 响应式设计，适配各种屏幕尺寸
- Fluent Design 设计语言
- 实时搜索和分页
- 状态徽章（成功/危险/警告）
- 统计卡片网格布局

### 实现文件
- `src/panel_html.rs` - 完整的前端 HTML/CSS/JavaScript

---

## 技术栈

### 后端
- **Rust** - 核心语言
- **Axum** - Web 框架
- **mysql_async** - 数据库驱动
- **tokio** - 异步运行时
- **serde/serde_json** - 序列化

### 前端
- 纯 JavaScript（无框架依赖）
- Fluent UI 设计系统（CSS）
- 本地存储会话管理

---

## 安全特性

### 认证
- 所有管理 API 都需要 admin token 认证
- Token 使用 MD5 + salt 哈希存储
- 30分钟会话超时（可滑动延长）

### 权限控制
- 所有破坏性操作需要确认
- 敏感操作记录日志

---

## 数据库表结构

控制面板使用以下前缀的表：
- `cp_admin` - 管理员 token
- `cp_visits` - 访问统计

依赖的 OJ 主表：
- `users` - 用户表
- `problems` - 题目表
- `submissions` - 提交表
- `discussions` - 讨论表
- `solutions` - 题解表

## 使用说明

### 首次启动
1. 启动服务器后，访问控制面板（默认端口会自动分配）
2. 首次访问会提示生成 admin token
3. 保存 token（仅显示一次）
4. 使用 token 登录控制面板

### 日常使用
1. 使用保存的 token 登录
2. 会话在30分钟无操作后过期
3. 可以在浏览器中保存 token 以便快速登录

## 开发者注意事项

### 添加新功能
1. 在对应的模块文件中添加业务逻辑
2. 在 `http_server.rs` 中添加 API 路由和处理函数
3. 在 `panel_html.rs` 中更新前端界面

### 数据库操作
- 所有数据库操作都是异步的
- 使用 `mysql_async` 的参数化查询防止 SQL 注入
- 记得正确处理错误并释放连接

### 性能优化
- 避免在循环中进行数据库查询
- 考虑添加缓存层
- 对大量数据使用分页
